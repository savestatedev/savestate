How to Set Up SaveState on a Fresh Machine

Node v22.23.3, npm 10.9.9, and @savestate/cli 0.9.0. Install, init, save, list, restore, then the MCP server.

This is a new-user pass on a clean Node 22 install of the published package @savestate/cli at version 0.9.0. The commands below are the ones that ran, and the transcripts are the text those commands printed.

The sources followed were the README quick start (npm install -g @savestate/cli, then init, snapshot, list, restore), the docs pages, and llms.txt (npm install -g @savestate/cli, then npx -y @savestate/cli mcp). For the adapter, see Claude Code. For the client config, see MCP and Cursor.

The machine

Node came from the official tarball node-v22.23.3-linux-x64, unpacked under /tmp/ss-clean. node -v printed v22.23.3. npm -v printed 10.9.9. PATH put that Node first, then /usr/bin and /bin.

Before the install there was no ~/.npmrc, no ~/.savestate, and no global @savestate/cli. Project commands used HOME=/tmp/ss-clean/home2. The global install itself used HOME=/tmp/ss-clean/home, which also had no SaveState config. The terminal was 120 columns by 40 rows, so the spinners could finish. The passphrase was the documented example your-passphrase.

The worked example is a Claude Code project that already contains CLAUDE.md. Before init, this file was created at ~/my-ai-workspace/CLAUDE.md:

# Workspace

This project is a Claude Code workspace used to try SaveState.

Preference: cocktail recommendations should mention the glass.

$ npx @savestate/cli --version

Exit code 0. The output included spinner frames, then 0.9.0, then the same npm upgrade notice as the install. The installed package.json description was Time Machine for AI. Backup, restore, and migrate your AI identity.

Init

Run in ~/my-ai-workspace, with the passphrase already exported. Elapsed 0.646 seconds. Exit code 0. Spinner frames were on the same lines as the status text.

$ export SAVESTATE_PASSPHRASE="your-passphrase"
$ npx @savestate/cli init

The banner still says Time Machine for AI. The character between SaveState and Time Machine for AI is U+2014. The transcript writes it as [U+2014].

~/my-ai-workspace/.savestate/config.json was written. storage.options.path is the absolute home directory ~/.savestate (/tmp/ss-clean/home2/.savestate). passphraseConfigured is true. The passphrase itself is not in the file. defaultAdapter is claude-code.

Connect the MCP stdio server

The Claude Code block from the MCP docs went into ~/.claude/settings.json. The Cursor block went into ~/.cursor/mcp.json. Both files were written exactly as those samples. The Claude Code file sets SAVESTATE_MCP_PASSPHRASE to your-passphrase-here. That string is the sample value. The CLI passphrase in the earlier commands was your-passphrase.

{
  "mcpServers": {
    "savestate": {
      "command": "npx",
      "args": ["-y", "@savestate/cli", "mcp"],
      "env": {
        "SAVESTATE_MCP_PASSPHRASE": "your-passphrase-here"
      }
    }
  }
}

Cursor, in ~/.cursor/mcp.json:

{
  "mcpServers": {
    "savestate": {
      "command": "npx",
      "args": ["-y", "@savestate/cli", "mcp"]
    }
  }
}

Claude Code and Cursor were not installed on this machine, so they were not restarted. The process those configs start was started directly, in ~/my-ai-workspace, with SAVESTATE_MCP_PASSPHRASE=your-passphrase-here.

$ npx -y @savestate/cli mcp

For the first two seconds, stdout was empty. stderr was:

SaveState MCP server running on stdio

A stdio client from @modelcontextprotocol/sdk 1.32.1, the copy installed with @savestate/cli@0.9.0, then called connect and listTools. That succeeded. serverInfo from the handshake:

{"name":"savestate","version":"0.5.0"}

Tools returned, four names:

  • savestate_snapshot
  • savestate_restore
  • savestate_list
  • savestate_status

The MCP docs page also lists savestate_search_snapshots, savestate_stats, the savestate_memory_* tools, and the OpenMemory-compatible names. Those names were not in this server's tools/list result. npm 0.9.0 does not expose them.
